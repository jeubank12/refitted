# PR descriptions

There is no PR template in this repo. Do not search for one or invent structure (no "Summary" / "Test plan" / "Changes" headings).

Remote sessions always open a PR when the requested work is complete — don't just push the branch and stop.

## Content

- Describe the change only: what the code now does differently. Not the process of getting there, not what was investigated, not what was tried and discarded.
- Never include a session link, `Claude-Session` trailer, or any reference to the assistant/session that made the change.
- No narrative: no "I", no step-by-step account of the work, no restating commit-by-commit history.

## Length

- Most PRs: one to two sentences.
- Larger PRs (many files, broad mechanical changes): keep it *shorter*, not longer — name the shape of the change, skip the minutiae. The bigger the diff, the less worth spelling out.
- Small, surgical PRs can afford one extra sentence of specific detail (e.g. the actual bug/fix) since there's little else competing for the reader's attention.
